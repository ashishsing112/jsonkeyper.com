About JSON Keyper

I'm Ashish Singh, a back-end developer. I built JSON Keyper because a large part of my working day is spent reading API responses I did not design, and I kept writing the same throwaway script to list every key path in them. This site is that script made public, plus the notes I have written up whenever a JSON problem cost me real time.

It is a one-person project. There is no company behind it and no team - when the contact page says someone will reply, that someone is me.

How It Started

JSON Keyper began in October 2024 as a deliberate stretch: I wanted to build something useful on the front end, outside the server-side work I was comfortable with. The first version did one thing - paste JSON, get a list of dot-notation paths. Features have been added as I hit cases it did not handle: arrays that needed collapsing into a schema view, keys containing dots that broke dot notation, TypeScript output for bootstrapping API clients, and an Execute cURL tab for when the response is easier to fetch than to copy.

The source is public on GitHub, and every change is listed on the changelog.

What the Tool Does

Paste a JSON document and JSON Keyper walks the whole structure, however deeply it nests, and gives you every key path in it. The same analysis can be shown six ways:

  • Key paths in dot notation, optionally with array indices collapsed so items[0].sku and items[1].sku become a single items[].sku - see Flatten JSON.
  • Key paths with value types, to spot an ID that arrives as a string before it causes a bug.
  • Unique key names, for a field glossary or comparing two API versions.
  • JSONPath expressions for jq, kubectl, and JSONPath libraries - see the JSONPath generator.
  • An indented tree for the shape at a glance - see the tree viewer.
  • A TypeScript type that merges records across an array, marking missing keys optional and null values nullable - see JSON to TypeScript.

How It Handles Your Data

JSON you paste is parsed by JavaScript in your own browser tab and never sent anywhere - you can disconnect from the internet after the page loads and it keeps working. The Execute cURL tab is the one exception: browsers block cross-origin requests, so it routes your request through a proxy I run to reach the API you named. The proxy does not log or store anything. The privacy policy has the details.

What It Does Not Do

The tool is deliberately narrow. Type inference describes the sample you paste, not the API's real contract. Very large documents can exhaust a browser tab, because the full path list is held in memory - at that scale, a streaming tool is the right choice, and this article measures the options. And it checks that JSON parses, not that it matches a schema; the JSON Schema guide covers that side.

How the Guides Are Written

I write the guides on the blog myself, about problems I have run into. I try to show evidence rather than repeat advice: the large-files article measures peak memory for each approach instead of repeating that jq streams (plain jq does not). When a guide is substantially revised, its date line says so. If you find something wrong, please tell me so I can fix it.
